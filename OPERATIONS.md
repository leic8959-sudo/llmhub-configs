# Запуск партнёрского распространения

Этот документ предназначен для оператора LLMHub. Он не содержит рабочих
кодов, сессионных данных или сумм вознаграждений.

## До выдачи ссылок и баланса

1. Войти в административную панель через dashboard session.
2. Прочитать и подтвердить актуальные условия платёжного compliance.
3. Проверить, что регистрация, пополнение, списание и возврат воспроизводятся
   по журналу использования.
4. Установить вознаграждение пригласившему и приглашённому только после
   утверждения экономики и лимитов антифрода.
5. Проверить сценарий двумя отдельными тестовыми аккаунтами.

Backend намеренно блокирует ненулевые `QuotaForInviter`, `QuotaForInvitee`,
перевод партнёрского баланса и создание redemption codes до подтверждения
compliance. Не обходите эту проверку прямой записью в базу.

## Партнёрский цикл

1. Создать отдельный партнёрский аккаунт или получить его `aff_code` через
   экран referral program.
2. Сгенерировать набор командой из README; один партнёр — один `aff_code` и
   один `utm_campaign`.
3. При необходимости создать ограниченную партию redemption codes:
   фиксированный номинал, срок действия, не более одного кода на пользователя.
4. Передать партнёру только публичную ссылку, инструкцию и выделенный код.
5. Еженедельно считать: переходы, регистрации, первый успешный API-запрос,
   первое пополнение и повторное использование на 8–14 день.
6. Отключать источник, если он создаёт регистрации без первых запросов или
   признаки мультиаккаунтинга.

## Минимальные события attribution

- `landing_view` с UTM;
- `account_created` с `inviter_id`;
- `first_api_success`;
- `first_topup`;
- `first_paid_request`;
- `retained_day_8_14`;
- redemption code, если он использовался.

Нельзя оплачивать партнёру показы или регистрации без сверки хотя бы с
`first_api_success`. Ключи API, содержимое запросов и персональные данные в
партнёрский отчёт не входят.
